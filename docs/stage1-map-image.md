## 2. 世界坐标映射（关键修复）

原实现把图片底边对齐到地面线，但**图片的地面在图片第 99 行、而非第 240 行**，
导致图片地形整体高出可站立地面约 141px（角色在图片岩壁下方"地底行走"）。

修正为按**图片行 → 世界 y 的线性映射**：

```
world(y_img) = y_img + 253
```

* 测得图片草皮线在 `img y ≈ 99` → `99 + 253 = 352 = GROUND_ROW × TILE`，正好是第 22 行顶。
* 只裁取内容带 `y 8..224`（3456 × 216）作为图层，置于世界 y = 261。
* 该层 `lock: true`，横纵均为 1:1 世界锁定（`src/gfx/bgLayer.ts`）。

### 像素级验收（严格证明）

## 3. 碰撞数据从图片提取（独立于像素）

`tools/stage1_extract.py` 从图片**数值化提取**交互地形，生成
`src/level/stage1ImageData.ts`（**请勿手改，重跑工具**）：

| 数据 | 说明 |
|------|------|
| `S1_GROUND_RUNS` | 岩石/草地质量 → 从地表行起 SOLID 到底 |
| `S1_BRIDGE_RUNS` | 金属桥面 → 第 22 行 SOLID 甲板 |
| `S1_WATER_RUNS` | 水体 → 可涉水，底部封顶保证能跳出 |
| `S1_PIT_RUNS` | 无底黑渊 → 留空，跌穿关卡即死（同原作） |
| `S1_WALL_RUNS` | 右侧要塞墙 → SOLID 整体（Boss 竞技场后墙） |
| `S1_SENSORS` | 武器箱面板 → 可击破 HIDDEN 瓦片（**不阻挡移动**，可穿过） |

提取器要点：
* 地表用「20 行窗口实体率 ≥ 85%」判定，且**只把岩石/草地/金属/墙体蓝算作实体**
  （水面与白色不算，否则水面会被误判成地面、桥体白色结构会被误判成岩壁）。
* 岩石纹理明暗抖动会让行号 ±1 跳变，故在**像素空间**做 ±2 列均值平滑后再取行号。
* 第一关宽度改为 **216 列**（= 图片宽度），与图片严格一一对应。

## 4. 渲染去重（图片即视觉）

第一关现在**只画图片**，不再把实心/水面瓦片美术重复画一遍

门、箱子、尖刺、梯子、平台等图片中不存在的对象仍正常绘制。

## 5. 唯一刻意偏离：Boss 竞技场平整

图片右侧（第 176–208 列，即最后一个满屏）是**裂缝深渊**。

**实测**：若原样保留，Boss 无法被击败——战斗机器人在两道深渊之间卡住，
28720 战斗帧后 Boss HP 停在 61.6（`tests/acceptance.test.ts` 失败）。
这与「必须保证可通关」的要求冲突，因此 `tools/stage1_extract.py` **只把竞技场**
（`BOSS_START = 176` 到关卡末）平整到第 23 行——即图片中要塞墙前最宽的自然平地
（第 195–202 列本就是第 23 行）。

* 竞技场内的 2 处无底渊与 2 个武器箱面板一并填入/移除（否则会被埋入实心地面）。
* **竞技场左侧的一切——包括裂缝深渊——与提取结果完全一致**，未做任何改动。

## 6. 待人工确认（不猜测，保留原图）

1. **渲染分辨率**：当前画布 640 × 360（16:9），原作 NES 为 256 × 240（4:3）。
   未擅自改动，需你拍板。
2. **第 2–8 关没有上传美术**（仅第一关有地图/瓦片/Boss 图），故保持程序化美术与
   手写瓦片地图，未把第一关素材拉伸复用。
3. **武器箱面板的可达性 —— 已解决（2026-10-13）**：实测发现把 `HIDDEN` 计入
   `isBlocking` 会让面板变成一堵实体墙，角色在 col 21 面板前被卡死（x=324 恰好是
   面板左缘）。原作中武器舱是**可穿过**的——不射击也能直接跑过去。因此
   `tiles.ts` 的 `isBlocking` 已移除 `T.HIDDEN`（仍保留 `isDestructible`，
   子弹可击破并掉落武器）。面板放置在 `grow-1` 行，恰好等于站立水平射击的
   枪口行（`groundTop − 0.58h`，h=22–23），奔跑中水平开火即可击破——
   浏览器实测 col 21 面板被击破（tile 8→0）。
4. **竞技场平整的观感**：角色在平整后的竞技场地面上行走时，图片中对应的裂缝区域
   看起来像"凌空走过"。这是可通关性优先的结果，如需改用其它方案（例如把 Boss 门
   移到裂缝之前）请告知。

## 7. 复现方式

```bash
# 提取碰撞数据（只读图片，生成 src/level/stage1ImageData.ts）
python tools/stage1_extract.py

# 叠加验证：把碰撞轮廓画到图片上分段目视核对
python tools/stage1_overlay.py

# 浏览器像素级对齐验收（需先启动 dev server）
node verify_pixel.mjs      # 画布像素 vs 地图图片像素，100% 一致
node verify_map.mjs        # 多点站位/接地/截图

# 浏览器完整通关验收（真实键盘驱动：跑动/射击/跳跃，直到 STAGE CLEAR）
node tools/accept_stage1.mjs
#   acc_1_start.png      开场：地图图片 1:1 渲染 + 武器箱面板在真实位置
#   acc_2_container.png  col-21 面板被击破（tile 8 -> 0）
#   acc_3_boss.png       Boss 战（DEFENSE WALL + 要塞墙美术）
#   acc_4_clear.png      STAGE CLEAR（TIME 31.05 / BONUS 1000）
#   结果：bossHp 100 -> 0（仅普通子弹伤害，无 F4/F5）、phase -> 'clear'、
#         state -> 'victory'、0 控制台错误。
#   注：脚本开启 debug.invincible 仅防意外死亡；机器人卡住时会前移一格
#   以保证截图完成——真实可通关性由 tests/traversal.test.ts 无头验证。

# 回归
npx vitest run             # 137 项全通过
npx tsc --noEmit
```
