## 2. 修改前的实际用法（并可复现的问题）

`packStage1Bg()` 切取整幅 `[0, 0, 3456, 240]`，装配为：

```ts
layers: [{ sprite, speed: 0.5, repeat: true, y: VIEW_H - 240 }]   // y = 120（屏幕坐标）
```

绘制代码：

```js
let ox = -((camX * l.speed) % w);                        // speed = 0.5
ctx.drawImage(l.sprite, x, l.y - camY * l.speed * 0.25); // 纵向速率 0.125
```

而承载碰撞的地形瓦片由 `drawTiles(ctx, camX, camY)` 以 **1:1 世界坐标**绘制。

→ **底图与碰撞地形使用两套不同的滚动速率**，必然错位。

### 量化验证（相机水平移动 200 世界像素）

画布内部 640×360，显示放大 2 倍 → 1:1 应为 **400 截图像素**。
用像素互相关（SAD）分别测量「底图带」与「地形带」的实际位移：

| 图层 | 修复前实测位移 | 与 1:1 的比值 |
|------|----------------|---------------|
| 地形（承载碰撞） | 400 px | **1.00** ✅ |
| 地图底图 | 200 px | **0.50** ❌ |

**结论：底图以一半速度滚动，与可站立地形分离。** 违反「地图视觉位置与实际碰撞位置必须完全一致」。

## 3. 修复（最小改动，不重绘地图）

1. `BgLayer` 增加 `lock?: boolean` —— 标记「此层即为关卡地图图片」，必须 1:1 锁定世界坐标。
2. 新增 `src/gfx/bgLayer.ts`：把偏移计算抽成纯函数（`bgScrollFactors` / `bgOriginX` /
   `bgOriginY` / `bgShiftForCamera`），`lock` 时横纵速率均为 **1**。
3. 第一关装配改为世界坐标锚点：

```ts
layers: [{ sprite: pb.sprite, speed: 1, repeat: true, y: pb.worldY, lock: true }]
```

`worldY = GROUND_ROW * TILE - 240 = 352 - 240 = 112`
→ **图片底边（world y = 352）正好落在地面线（GROUND_ROW × TILE）上**。

4. 装饰性视差层（其他关卡的程序化背景）行为**完全不变**。

### 修复后量化复测

| 图层 | 修复后实测位移 | 与 1:1 的比值 |
|------|----------------|---------------|
| 地形（承载碰撞） | 400 px | **1.00** ✅ |
| 地图底图 | 400 px | **1.00** ✅ |

底图带匹配残差 SAD 由 **4.9 降至 2.2**（对齐更精确）。浏览器 0 报错。

## 4. 碰撞数据独立于图片（未改动地图）

地形碰撞**不来自图片像素**，而来自独立数据 `src/level/layouts.ts → stage1Map`，
按你的第 2 条要求，已包含：

| 数据 | 实现 |
|------|------|
| 地面 | 连续 SOLID 基底，`groundRow(col)` 求每列地面高度 |
| 可站立平台 | `T.PLATFORM`（单向平台） |
| 墙壁 / 不可通过区 | `T.SOLID`、`T.CRATE`、`T.DOOR`、`T.HIDDEN`（感应墙） |
| 坑洞 / 危险区 | 浅 2 格 notch（有实心底，不会卡死）+ `T.SPIKE` 尖刺 |
| 梯子 / 可攀爬 | `T.LADDER` |
| 敌人生成点 | `buildWaves()` 按 x 触发的波次 |
| 机关 / 触发区 | 武器感应墙（HIDDEN 可击破）、Boss 触发 `bossArenaX() - 150` |
| Boss 区域 / 关卡结束 | `T.DOOR` 门 + `bossStart` 起点的平坦竞技场 |

**未假定「图片所有像素都是实心地形」** —— 图片只做视觉底图，零碰撞语义。

验证：出生点 `x = 48` 落在实心地（traversal 测试逐关确认）；
`tests/traversal.test.ts` 8 关全部可从出生点走到 Boss 门。
