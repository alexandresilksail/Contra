## 2. 世界坐标映射（关键修复）

原实现把图片底边对齐到地面线，但**图片的地面在图片第 99 行、而非第 240 行**，
导致图片地形整体高出可站立地面约 141px（角色在图片岩壁下方"地底行走"）。

修正为按**图片行 → 世界 y 的线性映射**：

```
world(y_img) = y_img + 253
```

* 测得图片草皮线在 `img y ≈ 99` → `99 + 253 = 352 = GROUND_ROW × TILE`，正好是第 22 行顶。
* 只裁取内容带 `y 8..224`（3456 × 216）作为图层，置于世界 y = 261。
* 该层 `lock: true`，横纵均为 1:1 世界锁定（`src/gfx/bgLayer.ts`）。

### 像素级验收（严格证明）

在 5 个不同相机位置冻结场景后逐点采样，**画布像素与地图图片像素 100% 一致**：

## 3. 碰撞数据从图片提取（独立于像素）

`tools/stage1_extract.py` 从图片**数值化提取**交互地形，生成
`src/level/stage1ImageData.ts`（**请勿手改，重跑工具**）：

| 数据 | 说明 |
|------|------|
| `S1_GROUND_RUNS` | 岩石/草地质量 → 从地表行起 SOLID 到底 |
| `S1_BRIDGE_RUNS` | 金属桥面 → 第 22 行 SOLID 甲板 |
| `S1_WATER_RUNS` | 水体 → 可涉水，底部封顶保证能跳出 |
| `S1_PIT_RUNS` | 无底黑渊 → 留空，跌穿关卡即死（同原作） |
| `S1_WALL_RUNS` | 右侧要塞墙 → SOLID 整体（Boss 竞技场后墙） |
| `S1_SENSORS` | 武器箱面板 → 可击破 HIDDEN 瓦片（**不阻挡移动**，可穿过） |

提取器要点：
* 地表用「20 行窗口实体率 ≥ 85%」判定，且**只把岩石/草地/金属/墙体蓝算作实体**
  （水面与白色不算，否则水面会被误判成地面、桥体白色结构会被误判成岩壁）。
* 岩石纹理明暗抖动会让行号 ±1 跳变，故在**像素空间**做 ±2 列均值平滑后再取行号。
* 第一关宽度改为 **216 列**（= 图片宽度），与图片严格一一对应。

## 4. 渲染去重（图片即视觉）

第一关现在**只画图片**，不再把实心/水面瓦片美术重复画一遍

门、箱子、尖刺、梯子、平台等图片中不存在的对象仍正常绘制。

## 5. 唯一刻意偏离：Boss 竞技场 40 列平整（门已移到裂缝前）

**用户拍板（2026-10-13）**：Boss 门改到**裂缝之前**，不再把右侧裂缝区压平。

* `BOSS_START = 100`：Boss 门（DOOR）立在 col 100，竞技场为单屏
  `[100, 140)`（40 列 == 一个 VIEW_W/TILE 屏），相机锁定该屏。
  裂缝（col 144+）与要塞墙（col 209+）**保持图片原样**，位于竞技场之外、
  从未被穿越。
* 竞技场窗口内的美术是**起伏的丛林高地（第 21–24 行）**，而 Boss 战需要
  一条连续、无坑的平地，因此**仅把这 40 列**平整到该窗口自身的众数地表行
  （第 21 行）。这是相对图片的唯一偏离，且严格限制在竞技场内。
  移除旧方案（平整 176–208）后，col 184–185 / 190–191 处图片里原本就有、
  此前被压平掩盖的两道无底渊重新按提取结果保留。
* **Boss 门立在竞技场地表上**（`stage1ImageMap` 第 6 步：门占
  `surfaceRow-6 .. surfaceRow-1` 行，而不是固定的 `GROUND_ROW-6` 行）。
  原因：`openBossDoor()` 会把门瓦片清成 EMPTY——若门盖住了地板行，
  开门后该列会塌掉一格，在竞技场地板上留下一个洞（单测实测抓到）。
* 敌波生成（`buildWaves`）随之改为**随关卡长度自适应**：波次间距按
  `usable` 缩放（短关更密），首波起点必须越过初始触发窗
  `cam.x + VIEW_W*0.75`，否则开场敌人会直接砸在出生点上
  （实测把首波放到 col 20 时，敌人开局把 P1 顶退了 39px）。

## 6. 待人工确认（已全部拍板，2026-10-13）

1. **渲染分辨率 —— 已确认 640 × 360**：`constants.ts` 的 `VIEW_W/VIEW_H`
   本就是 640×360，无需改动。
2. **第 2–8 关无上传美术 —— 处置确认**：保持各关程序化主题美术
   （`buildBackground(theme)` + 手写瓦片地图），不伪造素材、不把第一关
   素材拉伸复用。若日后上传第 2–8 关的地图图，可直接套用同一套
   「提取 → 世界锁定 → 碰撞独立」管线（`tools/stage1_extract.py` 模式）。
3. **武器箱面板的可达性 —— 已解决（2026-10-13）**：实测发现把 `HIDDEN` 计入
   `isBlocking` 会让面板变成一堵实体墙，角色在 col 21 面板前被卡死（x=324 恰好是
   面板左缘）。原作中武器舱是**可穿过**的——不射击也能直接跑过去。因此
   `tiles.ts` 的 `isBlocking` 已移除 `T.HIDDEN`（仍保留 `isDestructible`，
   子弹可击破并掉落武器）。面板放置在 `grow-1` 行，恰好等于站立水平射击的
   枪口行（`groundTop − 0.58h`，h=22–23），奔跑中水平开火即可击破——
   浏览器实测 col 21 面板被击破（tile 8→0）。
4. **竞技场 —— 已改方案**：Boss 门移到裂缝之前（见第 5 节），旧
   「平整 176–208」方案废弃；竞技场内图片自带的两个武器箱面板
   （col 103 / 115）保留为**纯视觉**（其 HIDDEN 碰撞已随竞技场平整移除，
   不阻挡、不可击破，跑动可直接穿过）。
